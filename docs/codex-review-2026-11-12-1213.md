# Codex review · 2026-11-12 12:13

Reviewed the FleetPulse working tree on top of `336a2e1`, including the screen refactor, the Playwright suite, and the fixes from the earlier browser sweep.

## Findings

### P1 · Prevent pending route writes from crossing a development reset

A cancellation started before reset can clear the assignment pointer of a truck assigned after reset. To reproduce, start a cancellation, reset the mock during its processing delay, and assign the same truck a new route. The old cancellation returns `200` and clears the truck's new assignment pointer. A second assignment then returns `201`, leaving two active routes for the same truck in the API. Before applying a delayed PATCH, verify that its captured route still belongs to the current fleet. [Delayed status update](../server.js#L306)

### P2 · Discard pre-reset save responses that arrive late

A route creation succeeded on the server while its response was held in the browser. Reset cleared the route list. Releasing the successful response restored the deleted route in the tab even though `GET /api/routes` still returned an empty list. Apply the reset generation check to write responses as well as pending reads. [Create response](../src/screens/routes/components/RouteForm.tsx#L77) · [Route store](../src/screens/routes/hooks/useRoutes.ts#L37)

### P2 · Reconcile deleted routes after reconnect

A dispatcher missed the reset while disconnected. After reconnect, the server returned an empty list, yet the old route stayed visible and **New route** was enabled. Reconnect should remove records cleared by the reset while preserving newer WebSocket updates received during the fetch. [Snapshot merge](../src/screens/routes/utils/routeState.ts#L17)

### P2 · Restore dispatcher presence after reset

After reset, two connected tabs each showed only their own dispatcher. One dispatcher still had Truck Alpha open, but the other tab lost that viewing indication. Reset clears the peer list while both sockets stay connected. Re-establish presence so open truck views and online dispatchers become visible again. [Presence reset handler](../src/components/dispatcher-presence/useDispatcherPresence.ts#L31)

### P3 · Make Playwright startup deterministic

The browser runner inherits the mock's random fleet `503` responses. Three consecutive failures can exhaust the app's retries before a navigation or route test reaches its scenario. Control startup failures in the browser suite and keep explicit coverage of `Retry-After` and retry exhaustion. [Test mock](../e2e/mock-server.mjs#L15) · [Fleet retry](../src/api/fleet/queries.ts#L4)
